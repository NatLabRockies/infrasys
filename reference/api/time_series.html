pydantic model infrasys.time_series_models.Deterministic¶

A deterministic forecast for a particular data field in a Component.

This is a Pydantic model used to represent deterministic forecasts where the forecast data is explicitly stored as a 2D array. Each row in the array represents a forecast window, and each column represents a time step within the forecast horizon.

Parameters:

  • data (NDArray | pint.Quantity) – The normalized forecast data as a 2D array.

  • resolution (timedelta) – The resolution of the forecast time series.

  • initial_timestamp (datetime) – The starting timestamp for the forecast.

  • horizon (timedelta) – The forecast horizon, indicating the duration of each forecast window.

  • interval (timedelta) – The time interval between consecutive forecast windows. A single-window forecast (window_count=1) has no second window to step to, so timedelta(0) is the natural value there and is stored and returned verbatim.

  • window_count (int) – The number of forecast windows.

data_array¶

Returns the underlying numpy array (stripping any Pint units if present).

Type:

NDArray

Transaction¶

The transaction object for time series operations, yielded by infrasys.system.System.time_series_transaction(). Call the time series methods on it to batch them together and to make them share one unit of rollback.

class infrasys.time_series_transaction.TimeSeriesTransaction(manager: TimeSeriesManager, context: TimeSeriesStorageContext, *, validate_owner: Callable[[Component | SupplementalAttribute], None])¶

One open batch of time series work, yielded by System.time_series_transaction.

Every method mirrors the System method of the same name and routes through this transaction’s batch: additions are buffered into one bulk write, reads see the batch’s staged work, and if the block raises, everything the transaction did is rolled back.

Examples

>>> with system.time_series_transaction() as txn:
...     for gen, ts in profiles:
...         txn.add_time_series(ts, gen)
property has_staged_data: bool¶

Return True if additions are buffered but not yet written to the store.

Readers¶

Readers return every matched component’s data at one timestamp, which is the transpose of what the other read methods provide. Build them with infrasys.system.System.build_time_series_reader() and infrasys.system.System.build_forecast_reader(). See How to read time series by timestamp for a worked example.

class infrasys.time_series_reader.TimeSeriesReader(store: Any, reader: Any, group_component_ids: list[tuple[int, ...]], units: dict[int, QuantityMetadata | None])¶

Reads the value of every matched SingleTimeSeries at one timestamp.

All series covered by a reader share one grid (initial timestamp, resolution, and length); the store rejects the build otherwise.

Examples

>>> reader = system.build_time_series_reader(timedelta(hours=1), name="active_power")
>>> for timestamp in reader.timestamps:
...     values = reader.read(timestamp)  # {component id: float}
property component_ids: tuple[int, ...]¶

Return the ids of every component covered by this reader.

property units: dict[int, QuantityMetadata | None]¶

Return each component’s stored units, or None where the series is unitless.

Values returned by read() are raw magnitudes in these units. Attaching pint quantities per value would dominate the cost of a stepping loop, so the readers leave that to the caller.

property grid: dict[str, Any]¶

initial timestamp, resolution, and length.

Type:

Return the shared grid

property timestamps: list[datetime]¶

Return every timestamp on the reader’s grid, in order.

Each timestamp is spelled the way the cohort’s series were written: naive for a zoneless cohort, aware otherwise. Feed them straight back to read().

read(when: datetime) → dict[int, Any]¶

Return {component id: value} for every covered series at when.

Raises:

InvalidParameterError – Raised by the store if when is not on the reader’s grid, or if it is spelled differently than the cohort — a naive when against series that record instants, or an aware one against a zoneless cohort. Use a timestamp from timestamps and the spelling always matches.

read_columns(when: datetime) → list[tuple[tuple[int, ...], Any]]¶

Return (component ids, values array) per columnar group at when.

The escape hatch for loops where building a dict per step is measurable: the arrays come straight from the store with no per-value Python objects. Each array is shaped (num_components, *element_shape) and aligned to its id tuple.

class infrasys.time_series_reader.ForecastReader(store: Any, reader: Any, component_ids: tuple[int, ...], slots: tuple[int, ...], units: dict[int, QuantityMetadata | None])¶

Reads the forecast window of every matched forecast at one timestamp.

Components whose forecasts are backed by the same array collapse to a single slot. The store performs one physical read per slot rather than one per component, and read() hands every component in a slot the same array object rather than a copy. read_slots() exposes the deduplicated form directly.

Examples

>>> reader = system.build_forecast_reader(timedelta(hours=1), name="active_power")
>>> for timestamp in reader.timestamps:
...     windows = reader.read(timestamp)  # {component id: ndarray of (horizon,)}

Return the ids of every component covered by this reader.

property units: dict[int, QuantityMetadata | None]¶

Return each component’s stored units, or None where the series is unitless.

property timeline: dict[str, Any]¶

initial timestamp, resolution, interval, and count.

Type:

Return the window timeline

property timestamps: list[datetime]¶

Return every window start timestamp, in order.

Each timestamp is spelled the way the cohort’s forecasts were written: naive for a zoneless cohort, aware otherwise. Feed them straight back to read().

property num_slots: int¶

Return the number of distinct windows, one physical read each per step.

This is at most len(component_ids), and smaller whenever components share a backing array — for example after System.transform_single_time_series(), or wherever many components were given the same profile.

property slots: dict[int, int]¶

Return {component id: slot}. Equal slots mean a shared window.

components_by_slot() → dict[int, list[int]]¶

Return {slot: [component ids]} for callers driving work per unique window.

read(when: datetime) → dict[int, Any]¶

Return {component id: window array} for every covered forecast at when.

Components sharing a slot share one array object, so a shared profile is materialized once no matter how many components carry it. Treat the arrays as read-only for that reason.

Raises:

InvalidParameterError – Raised by the store if when is not on the reader’s timeline, or if it is spelled differently than the cohort. Use a timestamp from timestamps and the spelling always matches.

read_slots(when: datetime) → dict[int, Any]¶

Return {slot: window array} at when, one entry per unique window.
